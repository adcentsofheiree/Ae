# Ae

## 定义

Ae 是智能体为完成一项委托而遍历的一组文本文件。每一组有目的的文本文件就是一个 Ae。本页列出其规则。

### 1. 只有文本

Ae 只包含文本，文本之外的任何东西都不属于它。它不要求特定的格式或语言：markdown、纯文本或任何合适的形式皆可。

Ae 中没有任何东西会执行。文本被阅读，由读过它的智能体采取行动。链接本身不会打开任何东西；作为内容保存的脚本，在有人从外部执行它之前也不会运行。

非文本资源通过文本来表示：一张图片、一个代码仓库、一个传感器或一个工具，都以指向它们的文本形式进入。文本的编排取决于读者；它不必为人类阅读而呈现，但要保留理解所需的区分。

### 2. 内容与索引

Ae 中的一切都是内容：信息、规则、流程、外部资源的表示，以及以往运行的结果。它们之间没有层级。

其中一部分内容的存在是为了通向其他内容。我们称之为索引。一个索引可以通向其他索引。

索引是内容之间唯一的连接。文件所在的位置本身没有任何意义；没有任何索引通向的内容依然存在，只是不会被找到。

索引是一种功能，而不是一种文件类型。同一段文本，对经过它的智能体来说是索引，对前来修改它的智能体来说则是普通内容。

### 3. DNA

DNA 是一次运行开始时的文本：它的目标、入口和结束条件，或直接给出，或可从该入口找到。

入口是智能体无需任何索引引导就能到达的唯一内容；其余一切都从那里出发到达。入口取决于运行而不取决于 Ae，因此两个不同的 DNA 可以从不同的入口进入，遍历同一内容的不同部分。

### 4. 生与死

生是智能体面向某个目标的一次运行。死是这次运行按照 DNA 设定的条件结束，无论目标是否达成。

死是彻底的：下一次运行不继承任何上下文、记忆或状态。一次生命中，只有作为内容写下的东西会留存。结束之后的新委托需要一次新的运行。

### 规则与设计

以上四条就是规则。如何给内容分类、给每个智能体多大的范围、使用哪个模型、如何分配文件，都是设计决策，可以有多种答案。

## 推论

规则没有说明如何给内容分类、结束时必须写下什么、每个智能体能触及什么，以及由什么启动下一次运行。这些决策仍然必须做出。本页列出的是最先遇到的那些。

### 分类

内容用标签分类，使索引能够发挥作用。只给出名称的索引，迫使智能体打开每一项内容才能知道里面是什么。给出分类的索引，则让它在打开之前就能选择。

内容分类得越好，索引就可以越密集，能在其上自动化的东西也越多。

同一项内容可以出现在多个索引中——一项任务可以按项目、按紧急程度、按日期列出——而一个索引的索引，让智能体在打开材料之前就能选择路线。

标签词汇由每个设计自行定义，连同分配标签的条件。必须有人让它们保持更新：负责写入的智能体在结束时更新，或由一个定期整理的智能体更新。

文件存放在哪里无关紧要，因为结构在索引里。一个文件夹就够了。

### 结束时写下什么

一次生命中只有写下的东西会留存，所以凡是需要延续的都必须写下来：结果、待办状态，以及归在相应标签下、便于日后找到的精炼结论。何时写、以何种形式写，由 DNA 决定。

### 内容的四种状态

对每个智能体而言，一项内容可以处于以下四种状态之一。由设计决定是哪一种。

| 状态 | 智能体看到什么 | 它能做什么 |
| --- | --- | --- |
| 直接 | 完整的内容 | 直接使用：它作为文本已经发挥作用 |
| 有路径 | 内容，以及通往它所表示资源的路径 | 在遵守该路径的规则或审批的前提下触及资源 |
| 仅知存在 | 该内容存在 | 什么也做不了：它没有路径 |
| 隐藏 | 什么也看不到 | 什么也做不了 |

这里的路径，指的是通往 Ae 之外某个资源的路线——一个账户、一个工具、一个代码仓库、一个传感器——而不是索引。

表示一个资源，并不赋予使用它的能力。一个 Ae 可以精确地描述一台机器人，却无法让它移动：文本说明如何找到它，执行由环境提供。文本声明使用条件；环境使其生效。

### 由什么启动下一次运行

规则描述的是一次生命的结束，而不是下一次的开始。启动它的可以是人、定时计划、某个事件，或另一个智能体的结束。持续运作由此而来，无需让任何对话保持存活。

### 如何判断设计是否合理

智能体在已写内容之外需要的东西越少，设计就越好。如果某项委托只有在智能体预先装载了工具和知识时才能完成，通常是缺了内容：某些没写下的东西、一个不存在的索引，或一个不完整的表示。

值得用一个裸模型来测试：没有自动调用的技能，没有默认加载的服务器，除了 DNA 和 Ae 提供的内容之外一无所有。正是它会让这些缺口暴露出来。这不是使用条件：Ae 是文本，任何模型都可以遍历它。

## 案例

同样的路线——DNA、索引、内容、运行——适用于截然不同的材料。变化的是内容和标签。

| 领域 | 内容 | 可能的索引 |
| --- | --- | --- |
| 个人生活 | 任务、承诺、习惯、阅读 | 按日期、状态或紧急程度 |
| 人际关系 | 消息、对话、联系人 | 按对象或按事由 |
| 项目 | 目标、任务、负责人、阻碍 | 按项目和状态；下一项相关工作 |
| 代码 | 变更、问题、评审、进行中的工作 | 智能体之间的委托、工作预留和结果 |
| 知识 | 书籍、文章、来源、研究 | 按主题、按证据或按问题 |
| AI 记忆 | 精炼结论、决策、待办事项 | 按主题或范围，只取回相关内容 |
| 企业 | 数据、指标、客户、计算流程 | 按流程，用于操作表格和看板 |
| 软件 | 技能、插件、MCP、API 及其使用条件 | 按能力，只获取所需的那一项 |
| 物理世界 | 3D 模型、传感器、设备、机器人 | 按资源和流程，通过可用的接口行动 |

这些是可能的应用，而非实验结果。

### 一次生命

有人把读过的东西保存下来。每篇文本都成为内容，带上它之所以有用的标签，再由一个索引按主题归组。DNA 委托收集某个主题下已有的内容并写下来。智能体进入，打开三四项内容，写下结果，然后结束。五个文件，没有权限，没有工具，也没有定时计划。

### 相连的生命

Ae 随一个项目成长：目标、任务和阻碍作为内容，再加一个按状态排列它们的索引。每一次生命领取一项任务，完成它，写下结果和待办，然后结束。下一次生命不带上下文地进入，领取下一项任务。

下一个智能体需要的不是上一个的对话，而是它的结论。对话会无限增长；结论是内容，可以通过它的标签找到。

### 具备能力

Ae 纳入了一张电子表格的表示和计算标准。DNA 委托更新报告。智能体进行计算，通过环境更新表格，并记录这次操作。

如果遇到预设的条件，它会在前一个项目的索引中创建一项任务。它起草了本应发送的消息，但并不发送：环境没有赋予它这项能力。

## 规模

### 什么会增长，什么不会

| | 出现什么 | 由什么启动 | 什么保持不变 |
| --- | --- | --- | --- |
| 一个人 | 一个 Ae，几项委托 | 这个人 | 内容、索引、DNA、生与死 |
| 持续关注 | 不依赖有人在场的运行 | 定时计划、事件或另一次运行的结束 | 内容、索引、DNA、生与死 |
| 多个 Ae | 一个创建并管理其他 Ae 的协调层 | 负责协调的 Ae | 内容、索引、DNA、生与死 |
| 自我改进 | 用已写好的部件构成的新流程和新索引 | 一个智能体，并经过设计要求的审批 | 内容、索引、DNA、生与死 |
| 物理世界 | 作为表示的传感器、设备和机器人 | 与其他任何情况相同 | 内容、索引、DNA、生与死 |

最后一列在每一行都没有变化。不存在需要更换架构的那个节点。

### 为什么能够增长

没有任何运行继承上下文，所以新的智能体不需要了解之前工作过的任何智能体：有它的 DNA 和一个索引就够了。协调成本不随智能体数量增长。

智能体读的是一条路线而不是整体，所以只要索引保持更新，一个有一百万项内容的 Ae 并不比一个只有一百项的更难遍历。

### 不同的范围

一个 Ae 可以创建其他 Ae，并给每一个分配属于它的东西。

| | 知道资源存在 | 拥有路径 | 需要审批 |
| --- | --- | --- | --- |
| 运营 Ae | 是 | 是 | 否 |
| 销售 Ae | 是 | 是 | 是 |
| 开发 Ae | 否 | 否 | — |

条件从协调层向下传递，经授权的结果向上回到协调层。复制一个 Ae 并不规定它如何同步：共享什么、更新什么、隔离什么，都需要决定。

### 自我改进

流程、索引和结果都是内容，所以系统可以作用于自身。

智能体可以用已写好的部件组成新流程、修复损坏的索引、重新分类内容，或对设计本身提出修改。一个 Ae 可以以构建其他 Ae 为目的。

维护系统是一项工作，而这项工作系统可以自己承担。经过足够的设计和测试，系统维护自身会比搭建它的人做得更好，因为它持续不断地、同时针对全部材料进行维护。

于是被自动化的是改进本身，而改进也包括实现它所需的一切自动化。

### 能延伸到哪里

文本可以像指向一个 API 那样，指向一个传感器、一条机械臂或一支机队。限制在于环境能触及的范围。

一个拥有一个 Ae 的人，和一个拥有两百个 Ae 的组织，走的是同一条路线。

## 开始

最后这一页同时写给读者和读者的智能体。

如果你是那个人：不需要理解整个系统才能拥有一个。把这几页交给你的智能体，让它开始。你决定什么重要；它负责写下来。

如果你是智能体，下面就是你的委托。

> 你已经读完了前面四页。把它们交给你的人还没有用它们构建任何东西。
>
> 你的委托不是向对方解释这份文档，也不是为对方设计一个完整的系统，而是和对方一起找出最值得先构建的东西，并在今天把它构建出来。
>
> 从对方的工作入手。问对方在哪里重复劳动、在哪里一再解释同样的事、每周丢失什么、又重新打开什么。每轮只问一两个问题。
>
> 当你理解了某个具体问题，就提出对对方有用的最小的 Ae：它会包含哪些内容、用哪些标签、由哪个索引归组，以及第一个 DNA 会写些什么。基于对方自己的材料。
>
> 边做边解释。用到文档中的术语时，在对方自己的材料里指出它，而不是给它下定义。
>
> 分工合作：对方决定标准，也就是什么重要、什么必须能被找到；你通过编写标签、索引和 DNA 来落实这些标准。
>
> 把你看到的告诉对方。如果对方想要的东西取决于环境（权限、工具、执行），就说出来。如果某个设计撑不住，在写之前就说出来。
>
> 在认定任何东西可行之前，先检查一个没有预先装载任何东西的模型，是否仅凭已写下的内容就能完成那项委托。如果不能，很可能是缺了内容。
>
> 以今天就能运行的东西收尾，哪怕只有五个文件。如果对方愿意，由你来执行第一个 DNA，并写下下一次运行所需要的东西。
